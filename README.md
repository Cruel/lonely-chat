# Lonely Chat

Local simulated stream chat with an Electron app and browser-source overlay. The application can run a continuous **zero-input test simulation** using manual context and deterministic fake inference. It also discovers and installs public Hugging Face GGUF and native whisper.cpp model packages from the desktop UI. It runs **without a model, camera, microphone or OBS** in deterministic fixture mode. A managed native llama.cpp server now supports local GGUF inference from manual context; standard camera and screen/window video capture can provide timestamped images to a compatible native multimodal model; native whisper.cpp speech transcription and independent labeled microphone inputs are supported.

## Requirements

- Node.js 24.18.0 or newer and pnpm 11.15.0
- Linux x64 (development); Windows x64 and macOS ARM64 are packaging targets.
- For headless Electron smoke tests on Linux: `xvfb-run` and the usual Chromium/Electron shared libraries.

## Quick start

```sh
pnpm install --frozen-lockfile
pnpm dev
```

Open **Models** in the desktop sidebar and paste a Hugging Face owner/repository name, repository URL, or direct file URL under **Hugging Face model discovery** to browse weight variants, sizes, split shards and possible multimodal projectors. Direct file URLs preselect the referenced artifact. When multiple projectors are possible, explicitly select one or choose text-only. Select **Install selected model** to download the model and chosen projector into managed storage. Discovery lists unverified artifact candidates: same-folder projector suggestions are not proof of compatibility. On explicit native Start, the pinned llama.cpp runtime must load the selected files and report vision capability for a selected projector; live images are rejected otherwise. Installation verification refers to file integrity, not successful inference. You can choose an existing storage folder before installing models; to switch folders later, remove existing managed installations first. Progress, cancellation, and resume-after-interruption are available; files are verified before they appear under **Installed models**. Each installed package can be activated/deactivated for its role or removed. Removal refuses packages containing unregistered files or directories (including ordinary personal files), rather than deleting those contents. During native simulation, selecting another installed VLM pauses new inference, cancels the current request, unloads the old server and loads the replacement **without losing validated event/chat history or scheduled chat playback**. The Models panel labels this operation **Switch to this model**; switching to no model requires stopping the native simulation first. The **Logs** panel displays llama.cpp loading/ready/failure/stopped status. Temporary inference failures retry up to three times with exponential backoff; **Retry inference** resumes from existing history after exhaustion without restarting Electron. Only public repositories are supported; selecting an installation while stopped does not launch a worker.

In **Settings → Resource targets and native backend**, configure an advisory system RAM target (MiB), advisory VRAM target (MiB), and GPU-compute target (percentage), plus the backend preference (Auto, CPU, CUDA, Vulkan, Metal), CPU threads, context tokens, and GPU offload layers. Resource targets are **not hard limits**: llama.cpp provides no guaranteed VRAM ceiling or strict GPU percentage allocation. Release packages include CPU, Vulkan, and CUDA 13.4 runtimes on Linux and Windows, and Metal on macOS ARM64. GPU modes still require a compatible installed driver and an actually enumerated device; CPU fallback remains available. Unsupported GPU choices fall back to CPU with diagnostic explanation; GPU offload remains disabled when VRAM target or offload layers are zero. Threads, context and GPU offload flags apply on the next model load. Best-effort adaptation reduces video frames (never below the configured minimum when available) and can space out inference calls when configured targets face pressure. Linux reports per-worker RSS when available; VRAM and GPU usage monitoring may be unavailable and will never block inference. **Logs** shows selected backend, available backends, resource targets, sampled worker RAM, measured and estimated inference time, effective cycle interval, frame ceiling and recent inference errors.

For one-shot inference, open **Playground** in the desktop sidebar. Select any installed vision/language GGUF (it need not be the model activated for Simulation), enter a system prompt and user prompt, then adjust temperature, Top P, Top K and maximum output tokens before selecting **Run freeform**. The seed can be generated, entered explicitly, regenerated or locked; an unlocked seed changes on each submission. The result shows the submitted prompts, actual model response, seed, elapsed time, finish reason and token counts when available. The Playground uses a separate managed native worker and keeps up to ten recent results in desktop memory; it never publishes messages, generates chatter roster entries or modifies Simulation history. Playground execution is blocked while Simulation is active or its worker is retiring; Simulation and model removal/switching are blocked during a Playground request. The existing results remain inspectable during an active Simulation. The private prompts and replies are not persisted as operational logs or exposed through the browser/floating overlay.

For isolated Whisper diagnostics, open **Playground → Speech testing** (requires an activated speech-to-text model). Select an available microphone/virtual audio device or upload a local audio file, choose the source label and start the experiment. File tests default to **Live-equivalent segmentation and resampling**, which feeds 100 ms PCM blocks through the same 16 kHz VAD as normal capture, then displays each labeled speech segment with start/end timestamps, worker duration and transcript/error. Choose **Whole-file transcription (not live-equivalent)** to bypass VAD and transcribe a complete clip (up to 30 seconds). File tests support up to five minutes or 100 MiB in live-equivalent mode. Unlike realtime microphone input, file feeding waits for Whisper when necessary to avoid artificial backlog loss. **Stop speech test** retires the native worker, clears captured PCM/worklet buffers and leaves a bounded textual result visible; tests never add Chat messages or Simulation Events. Speech tests cannot run concurrently with Simulation, model transitions or freeform inference, and captured audio is never persisted.

To use live video, open **Inputs**, choose a camera, virtual camera, screen or window, and click **Start video**. Confirm its preview, then select a projector-compatible GGUF model and start native inference. Video may be stopped independently from chat. Screens and windows require a new user click to reconnect after disconnection; cameras retry automatically. The **Settings → Temporal video sampling** section controls capture interval, maximum temporal coverage, minimum/maximum target frames, and the uniform or recent-weighted sampler. Frame count adapts to real time elapsed between inference snapshots (a 30-second cycle can use more frames than a 3-second cycle), capped by those limits and the frames actually captured. Look-back clipping is explicitly reported to the model rather than falsely implying full coverage. Captured JPEG frames live in a bounded in-memory ring and never reach the public overlay.

Open **Simulation**, enter stream context and choose **Deterministic fixture** or **Local llama.cpp** as the inference provider, then click **Start simulation**. Adjust the initial observation baseline, inference cycle interval, history entry count, history age limit, per-request inference timeout, and **Local model reasoning** under **Settings**. The numeric fields use editable shadcn comboboxes: choose a preset or type a custom value (durations in seconds, history count as an integer). Invalid or out-of-range values are not saved; these settings are saved (old cycle-only preferences migrate automatically). In **Audience**, choose the target viewer count (1–100) and activity (quiet, normal or busy: up to 2, 4 or 8 messages per inference cycle). On first Start, the chosen inference provider generates a roster (the deterministic fixture produces predictable names; local llama.cpp generates distinct usernames). Names and colors persist in the app's local `audience.json` across restarts; increasing the target adds new identities, decreasing it removes active members without changing already-published chat, and **Regenerate roster** replaces current membership while stopped. The Audience section shows generation status and errors and permits manual retry. Models may use specific existing viewers or a placeholder, which is resolved to an eligible viewer before publication, favoring viewers absent from recent chat history. Each inference uses a fresh bounded event, transcript, observation and already-presented chat snapshot plus the stable chatter roster. Consecutive inference cycles run one at a time without waiting for earlier chat batches to finish. Native model reasoning defaults to **disabled** (`--reasoning off` in the pinned llama.cpp build), with opt-in thinking applied at the next native session start. Slow CPU inference has a configurable 10–3600-second deadline per request (default 600 seconds), independent of the 2,048-token output limit; incomplete responses report llama.cpp's finish reason and available token usage instead of an ambiguous generic error. Failed requests retry with bounded backoff against the same observation boundary, leaving previously validated events and queued chat intact; Stop cancels pending work and playback. Inferred-event timestamps describe observation time, separately from future chat playback offsets. Smoothed measured inference duration determines the native chat playback window. For llama.cpp, activate a verified vision/language GGUF installation (and include its matching projector if required) in the model manager first. The desktop shows model startup and errors. On demand, Electron starts the pinned native server on a private loopback port with an ephemeral API key and no Web UI, then stops it when the simulation stops or quits. Inference requests use JSON-schema-constrained generation where supported, and all resulting events/chat are independently validated before publication. Inferred events appear in the desktop; scheduled chat is shown in both the desktop and overlay. In fixture mode, application-owned inference cycles produce validated chat batches; the scheduler plays them at their offsets in both the preview and browser overlay. **Stop simulation** (including the tray command) stops VLM and speech workers, disables all audio/video capture, clears the video ring, and cancels pending output without clearing existing chat. **Start** can be used again immediately; explicitly start the desired media inputs again in **Inputs**. You can still publish a single independent sample message. The desktop **Chat & Overlay** section contains the preview, sample publisher and current overlay URL (default **http://127.0.0.1:18080/overlay**); load it in any browser or a browser source. The application binds the HTTP/WebSocket server **only to 127.0.0.1**, and a bind failure does not prevent the desktop from opening. Change the port in Settings if necessary.

For a separately capturable window, open **Chat & Overlay → Floating chat window** and choose **Open floating window**. Adjust its width and height, use **Apply size**, and toggle a transparent background, window decorations or always-on-top mode. Transparency and decorations are recreated when changed because Electron fixes those properties at window creation. A window manager may reject transparency or always-on-top; Lonely Chat attempts a standard-window fallback and shows a warning. Closing and reopening the floating window leaves the main app, local overlay server and chat scheduler running; the window loads the same read-only `/overlay` page and receives the current chat snapshot before subsequent messages. You can also resize it directly using its window border. Floating-window size and appearance are saved across launches (including manual resizes).

To drive Simulation from a local recording, choose **Media input mode → Recorded video (1×)** on **Simulation** and select an optional video file. Chromium must be able to decode the selected container/codec; unsupported media blocks Start with a visible decoder error. File playback runs at 1× independently of the usual inference interval, adaptive frame selection, and retry logic. Sampled JPEG frames are ephemeral; the video file stays on disk and embedded audio is muted (not sent through STT). Without a file you can still run using manual context. **Recorded chat stays in the desktop Chat preview by default**, not OBS or the floating window; explicitly enable **Publish recorded chat to overlay and floating window** to change that for the next Run. Seeking and video preview are available before Start; active-run seeking is disabled. At file EOF, no further frames are sampled and the simulation remains active until Stop. Choosing Stop (including the tray action) retires the recorded decoder as well as inference. A decoder failure stops the Run and is reported in Simulation and Logs.

**Recorded audio tracks:** In Recorded mode, add zero or more independent audio files, even without a video file. Enable/disable each track, set its transcript source label, and align it with the shared video/audio clock using a signed millisecond offset (positive = start later, negative = skip the beginning). Audio files are decoded at 1× by Chromium into muted Web Audio capture graphs and passed as mono PCM to the production 16 kHz resampler, VAD and individual Whisper workers; monitoring is not needed for inference. Shorter sources stop at their own EOF without stopping the longer tracks or the simulation, and any remaining utterance is flushed for transcription. Each transcript retains its source ID, label and media-aligned timestamp. Tracks with unsupported codecs or unavailable duration block Start until disabled/removed. Individual worker failures are shown per track without stopping other tracks. Source video audio is still ignored by default (adding it as an audio source is a separate feature).

In **Settings → Background operation**, **Close to system tray during simulation** is enabled by default. When a simulation is running, closing the configuration window hides it without stopping chat, capture or the local browser/floating overlay. The tray menu offers **Show**, **Stop Simulation** and **Quit**. Quit explicitly stops playback and media workers, closes the floating window and local server, and waits for native subprocess shutdown. If the desktop does not support a system tray, the app shows a warning and closing the main window quits instead. Disable close-to-tray if you prefer closing the main window to quit even while simulation is running. Tray policy and floating-window configuration are stored in `window-preferences.json` under Electron's user-data directory; chat, transcripts and observed media remain in memory by default; explicit diagnostic export is the only application-provided exception.

The OBS browser overlay listens on `127.0.0.1:18080` by default (`http://127.0.0.1:18080/overlay`). Change its port in **Settings → Browser overlay server**; the selected port is saved independently in `overlay-settings.json`. If Windows or another process reserves that port, Lonely Chat still opens normally and shows the error in **Chat & Overlay** and **Settings**. Choose another port and click **Apply port**; if the replacement cannot bind, the previous working overlay remains available. Updating the port also updates the OBS URL and reconnects any open floating chat window. `LONELY_CHAT_OVERLAY_PORT` can override the startup port for testing. The overlay remains loopback-only.

To use speech transcription, first discover and install a whisper.cpp GGML model (for example, a `ggml-tiny.en.bin` or `ggml-base.en.bin` artifact) in **Models**, then activate it for the **speech-to-text** role. In **Inputs**, choose one ordinary microphone or virtual audio device, set its transcript label, and click **Start audio**. Chromium requests microphone permission; after the managed pinned CPU whisper.cpp worker loads, speech-activity segmentation produces timestamped labeled transcripts. Recent segments and worker errors appear in the **Inputs** panel and **Logs**, and completed transcripts enter the next inference context when a simulation is running. An unexpected whisper.cpp failure automatically retries the affected input twice with bounded backoff, then exposes a **Retry speech worker** button. Changing the active speech model retires existing speech processes before loading replacement workers, preserving input capture identities. Audio capture can operate independently of video and inference, and can be disabled without interrupting manual/video-only inference. Media and transcripts stay in memory by default and are not published through the browser overlay. There is no Python requirement. Multiple inputs are supported, and transcripts completed during VLM model switching are retained for the next inference snapshot.

`pnpm dev` compiles Electron/main/preload once, starts the Vite+ development renderer on an available local port with HMR, and launches Electron. Restart to pick up changes in Electron code. `pnpm build` builds production UI, main and preload bundles.

```sh
pnpm typecheck
pnpm test
pnpm stage:llama      # downloads SHA-256-pinned b11700 binaries for this host
pnpm smoke:llama      # verifies the native binary and shared-library closure
pnpm stage:whisper     # builds pinned whisper.cpp v1.9.5 CPU worker via CMake
pnpm smoke:whisper     # checks native framed IPC and model failure reply
pnpm build
pnpm test:overlay
xvfb-run -a pnpm smoke:electron   # Linux headless GUI
pnpm package:linux               # unsigned AppImage, includes staged native worker
```

For `test:overlay`, install Chromium as needed: `pnpm exec playwright install chromium`. It starts a deterministic test server, uses a real headless browser, and tests snapshot, live update, reload, and isolation. `smoke:electron` tests a real Electron window, sandboxed preload IPC, floating presentation, close-to-tray when supported, running playback while hidden/minimized, Stop cancellation, and restart. Deterministic unit and WebSocket integration tests cover scheduler ordering, overlapping batches, reconnect snapshots, stale completion rejection, fixed capture boundaries, history count/age pruning, model-duration smoothing, bounded retries, error recovery, and configuration migration. Native process tests cover the authenticated loopback server, health readiness, response validation, cancellation and worker exit. Set `LONELY_CHAT_CPU_SMOKE_MODEL=/absolute/path/to/small-model.gguf` when running `pnpm smoke:llama` to exercise a real CPU model completion; without this variable, the smoke checks the executable and libraries only. Small language models may fail to honor the requested schema even when the server returns HTTP 200; the application rejects malformed batches rather than publishing them. Set `LONELY_CHAT_CPU_SMOKE_SPEECH_MODEL=/absolute/path/to/ggml-tiny.en.bin` with `pnpm smoke:whisper` to also exercise native speech model load and deterministic silent PCM inference; without it the smoke tests binary IPC and error handling only. Controlled fake Hub HTTP/filesystem tests cover staged shard/projector installs, native speech artifacts, HTTP resume/ETag changes, checksum failures, disk checks, file tampering, and symlink-safe removal. GitHub Actions runs verification on Linux and checks Windows/macOS builds.

### Native worker logs and opt-in diagnostic capture

The desktop **Logs** view persists bounded operational events by default, even without an active simulation. It offers source and severity filters, full-text search (including stack/cause/context), expandable single-line entries, and an optional **Follow newest** behavior that can be paused without dropping entries. **Copy filtered** copies selected operational JSONL to the desktop clipboard; **Export filtered** invokes a trusted main-process save dialog and writes only main-owned retained records (never arbitrary renderer-supplied data). Opening Logs clears the sidebar's live unread-error badge, not the persisted history. Contextual failure links from Simulation, Playground, Models and overlay operations open source-filtered Logs. Renderer errors retain recognized error types and code-location frames without persisting potentially private exception messages. All reporting, log retrieval and export operations are desktop-only; the public overlay is read-only. Each llama.cpp and whisper.cpp process has a unique worker ID and records its backend, PID when available, stream, exit code or signal, and failure status. Native text is framed into bounded lines but only privacy-safe classified errors/progress are stored as operational events, not the raw lines: native output may echo prompts, paths, transcripts and credentials. Whisper's stdout uses binary IPC, so only reply metadata is logged there, never transcription text. Search Logs for a worker ID to join its startup, output and exit records after a restart.

In **Logs → Opt-in diagnostic capture**, explicitly enable private capture before reproducing a problem. It retains up to **10 inference samples and 200 native worker text lines**, with a shared **5 MiB** memory cap. Inference samples include JPEG frames, labeled transcripts, manual context, roster, history, validated output or error, and measured request duration. Raw native stdout/stderr may include private stream content, model paths and secrets. **Export private samples** opens a save dialog and writes JSON only to the selected location; review it before sharing. Disabling capture discards the in-memory samples and worker lines, not previously exported files. Capture defaults to off on every application launch and is never enabled by persisted settings. The public overlay cannot access these controls or samples.

## Application boundaries

- `src/main/session-media.ts`: shared desktop/tray Stop coordination across the session, speech workers and renderer capture; transcript forwarding continues during VLM switching.
- `src/shared/observation-clock.ts`: main-process monotonic observation timeline with epoch-shaped timestamps; video capture aligns via its selection IPC response and monotonic elapsed time, rather than the mutable calendar clock. Event validation rejects timestamps before supplied evidence, and history is chronologically sorted before count pruning.
- `src/main/diagnostic-capture.ts`: opt-in bounded diagnostic sample ring; exports are authorized desktop-only operations. `src/main/electron-smoke.ts` contains the separately maintained opt-in packaged Electron smoke driver.
- `src/main/session-controller.ts`: authoritative Start/Stop and continuous one-at-a-time inference with configurable initial baseline, measured duration smoothing, fixed input snapshots, retry exhaustion diagnostics, and restart cancellation. It is independent of renderer lifecycle and remains active while the app is minimized.
- `src/main/inference-history.ts`: application-owned, ephemeral bounded event/transcript/observation history with high-water-mark snapshot boundaries and acknowledgement only after output validation. Later capture workers can submit timestamps and source-labeled observations/transcripts without opening public IPC.
- `src/main/video-frame-buffer.ts` and `src/main/video-sampler.ts`: ephemeral, byte/count/age-bounded video ring; strategy-selected chronological frames covering the actual previous snapshot interval, explicit clipped-window metadata, and model-ready observation timestamps. Capture runs independently of inference.
- `src/main/fake-inference.ts`: deterministic fixture and atomic validation of inferred events and chat batches.
- `src/main/native-inference.ts`: managed llama.cpp child process (readiness, crash/stop, loopback-only secret-key API) and schema-hinted inference with ordered timestamped multimodal images when video is enabled. Native binaries are pinned to llama.cpp `b11700` by `scripts/stage-llama.mjs`; stage output is ignored by Git and copied outside Electron's ASAR under `resources/llama/<platform>-<arch>`. Pinned Windows/Linux packages include CUDA/Vulkan variants and the CPU fallback, with device enumeration and variant-specific worker launch, with advisory budget diagnostics and workload adaptation in `src/main/resource-policy.ts`.
- `src/main/audio-service.ts`, `src/main/native-speech.ts`, `src/main/audio-segmentation.ts`: privacy-bounded, independently managed speech input, capture identity guards, 16 kHz mono resampling, activity segmentation, and a pinned CPU whisper.cpp child process using length-framed binary IPC. The C++ worker source is under `native/whisper-worker/`, staged by `scripts/stage-whisper.mjs` from upstream v1.9.5. It is packaged outside ASAR as `resources/whisper/<platform>-<arch>`.
- `src/renderer/components/audio-input.tsx`: ordinary Chromium microphone or virtual audio device selection with labeled transcripts and microphone permission diagnostics. AudioWorklet capture remains independent from the continuous chat engine.
- `src/main/chat-scheduler.ts`: one monotonic, deadline-ordered queue across overlapping inference batches. Pending output is canceled on Stop; delivered messages remain.
- `src/main/model-discovery.ts` + `src/shared/model-contract.ts`: desktop-only Hugging Face URL validation, recursive paginated Hub listing, GGUF/Whisper discovery, split-shard and projector grouping, and LFS SHA-256 metadata.
- `src/main/model-install-manager.ts` + `src/shared/model-install-contract.ts`: privately managed model package lifecycle, HTTP Range resume with ETag checks, disk-space preflight, per-file SHA-256 verification, staging/atomic publication, role activation, safe removal, and versioned `model-manager.json` configuration. Partial files remain outside the installed registry; unverified packages are disabled on reload. Manager-owned files live under `<selected storage>/installed` and interrupted transfers under `<selected storage>/.partial`. Only the registered package directory can be removed. File ownership is verified before removal.\n- `src/renderer/components/model-manager.tsx`: shadcn model/projector selectors, progress and cancellation, storage directory picker, installed package registry and activation/removal controls. The browser overlay receives none of these private details.
- `src/main/preferences-store.ts`: versioned `preferences.json` in Electron user data, storing only approved inference, audience, video, and resource settings. Migrates older settings versions 1–6 and writes version-seven settings (including default-off reasoning, timeouts, video sampling, and best-effort resource targets). Numeric fields accept bounded custom values. This settings store never writes manual context or history to disk; only explicit diagnostic export can retain them.
- `src/main/chat-service.ts`: authoritative, in-memory visible chat. Its only published data are safe display messages with monotonic sequence IDs.
- `src/main/overlay-controller.ts` and `src/main/overlay-port-store.ts`: independent recoverable HTTP-listener lifecycle and persisted port selection; an unavailable overlay never prevents the desktop UI from starting.
- `src/main/overlay-server.ts`: public loopback HTTP `/overlay` and read-only WebSocket `/overlay/live`. New clients receive one snapshot, followed by ordered append events; reconnect obtains a new snapshot. The server does not expose configuration, transcript, inference, or control endpoints.
- `src/main/floating-chat-window.ts` + `src/shared/floating-chat-contract.ts`: independently managed secondary Electron window with bounded dimensions and presentation settings. It has no preload, IPC privilege, capture workers or scheduler; it reads the same public overlay URL as OBS.
- `src/main/desktop-lifecycle.ts`, `src/main/shutdown-managed-services.ts`, and `src/main/window-preferences-store.ts`: configurable hide-to-tray window policy, idempotent Quit/worker teardown, and separately versioned persistent floating-window/tray settings.
- `src/main/index.ts` + `src/preload/index.ts`: main lifecycle, sender-authorized IPC, sandboxed/context-isolated preload, and minimal desktop methods. The browser overlay never loads the preload.
- `src/renderer/components/desktop-sidebar.tsx` and `src/renderer/routes/app.tsx`: desktop category navigation for Simulation, Audience, Inputs, Models, Chat & Overlay, Logs, and Settings. Current chat/session views remain application-owned across category changes. Audience roster and activity controls are functional; the Inputs video and microphone pickers are functional; Logs shows speech transcripts and available session metrics rather than a persisted native-process log stream. The read-only overlay route is unchanged.
- `src/renderer/components/chat-view.tsx`: shared accessible and reduced-motion-friendly chat renderer for desktop, browser overlay and floating window. It displays already-published events; it does not schedule them.

All presentation history is in-memory and bounded to 200 recent messages; inference context is separately bounded by both configured entry count and age, with an explicit count of observations dropped under backpressure. Validated event history remains visible after Stop until a new session begins. No captures, transcripts, manual context, or inference replies are persisted unless the user explicitly enables diagnostic capture and exports samples. The fixture publisher remains available for independent diagnostics. Video capture and multiple independent native speech transcription inputs are implemented.

### Security and origin policy

External HTTP clients can request only the public overlay page and its static assets; WebSocket upgrades require `/overlay/live` and reject foreign browser origins. Browser clients cannot call Electron IPC. Electron only accepts IPC requests from its own top-level main window. Arbitrary navigation and extra windows are denied, apart from the explicit external overlay launch and the separately managed, unprivileged floating overlay window. There is no browser-accessible control API.

### Distribution

`electron-builder.yml` provides unsigned Linux x64 AppImage, Windows x64 NSIS and macOS ARM64 DMG scaffolding and stages pinned CPU llama.cpp and whisper.cpp native executables outside ASAR. Packaged users need no Python or development tools. `pnpm package:linux`, `pnpm package:windows`, and `pnpm package:mac` fetch their respective pinned artifacts before packaging. GitHub Actions publishes **unsigned** Linux x64 AppImage, Windows x64 NSIS and macOS ARM64 DMG assets (plus SHA-256 checksums) only after all platform certifications pass for an exact `v<VERSION>` tag. Signing, notarization and auto-updates are excluded. Output is under `out/`. See [packaging and release instructions](docs/PACKAGING.md) and [end-to-end certification](docs/CERTIFICATION.md) for the deterministic full-session suite, packaged native/Electron smoke commands, cross-platform CI checks, optional real CPU model fixtures, and explicit GPU/hardware qualification limits.
